Method

How the levels were set

  • 5 · verified: committed fixtures pass through this stage and an oracle (objdump, the host CPU, the original program's output) agrees.
  • 4 · working: the code exists and is exercised by tests, but nothing outside asm checks the answer yet.
  • 3 · partial: the code exists for part of the stage, or only for a related target (for example the ARM64 decoder that the Switch would reuse).
  • 2 · carded: defined cards with acceptance criteria are on the roadmap. blocked marks cards waiting on a missing tool or a decision.
  • 1 · envisioned: an endgame section names it (phases 4–11), with no cards yet.
  • 0: nothing yet.

Line, test and card counts are measured. Levels are judged from those counts plus the accepted cards' acceptance criteria, so treat them as ±1. The "retail" column means one commercial program from your own copy, carried from boot to its title screen (card 100, §422). No platform has reached it.
