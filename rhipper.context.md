# Rhipper Asm

The disassembly and lifting core of Rhipper, in pure Rust: a Windows PE image in, an LLVM-IR-shaped IR out, and C, C++ or Rust source out of that IR that builds and runs. It replaces Ghidra and the Python pipeline in the Rhipper Workbench (`../rhipper-ide`, an IntelliJ fork; its plugin is `plugins/rhipper`, its plan for this engine `docs/rhipper/rhipper-asm.md`). The roadmap is `rhipper.md`; a task is a card on it; you are the worker of one card.

## Layout

- `crates/ra-asm-format` — the little-endian cursor; every refusal names the offset and the field
- `crates/ra-asm-pe` — the PE loader: headers, sections, imports, exports, relocations, the exception table, TLS, the debug directory; `Image` with RVA/VA/file-offset conversions and bounded reads
- `crates/ra-asm-arch` — the neutral `Instr` record and the `Arch` trait a second architecture implements
- `crates/ra-asm-x86` — the x86/x64 decoder over iced-x86 (`decode.rs`), the register table (`registers.rs`)
- `crates/ra-asm-analysis` — functions (`lib.rs` fixpoint of seeds and descent, `builder.rs` blocks), jump tables, no-return, RTTI classes (`rtti.rs`), calls through a register that holds an import (`imports.rs`)
- `crates/ra-asm-ir` — the IR: types, instructions, modules, the `.ll` printer, dominators
- `crates/ra-asm-lift` — the lift: `x86.rs` (one match arm per mnemonic), `x87.rs`, `state.rs` (the `%State` machine model and the runtime globals), `data.rs` (data sections as globals), `raise/` (promote, abi, stack, frame, conditions, simplify, dce, widths, known, stubs, prototypes = the import prototype table)
- `crates/ra-asm-emit` — `structure.rs` (language-neutral structuring), `c.rs`, `rust.rs`, `functions.rs` (the function table)
- `apps/ras` — the CLI and the engine of the workbench: `info|disasm|functions|cfg|lift|signatures|emit|pipeline|serve`; `serve.rs` is JSON-RPC over stdio; `templates/CMakeLists.txt`
- `runtime/` — `rhipper.h` and `driver.c` (the C runtime and the host driver of a port), `rhipper.rs` (the Rust runtime); embedded in `ras` and written under a project's `gen`
- `testdata/` — `src/*.c|cpp` fixtures, `build.ps1` builds them with clang+lld into `bin/` (64 and 32), `expected/*.txt` their native output; `rhtest/` the old pipeline's MSVC-built test programs (`src/`, `<name>-<variant>.exe|.map`, `<name>.txt`)
- `rhipper.md` is tracked here (the roadmap is part of the record); `var/` and `out/` are not. `out/` is the scratch directory for ports and traces.

## Entry points

Start a card that spans these crates from the definition, not from a whole-file read.

- `builder::build` (`crates/ra-asm-analysis/src/builder.rs`) — builds one function's blocks: the `Image`, the `&dyn Arch`, the entry address, the code ranges, the known function starts, the no-return set and the C++ exception frame if any; gives a `Built`. `analyze(&Image)` / `analyze_with(&Image, &Facts)` in `lib.rs` run it over every function into an `Analysis`.
- `lift_with` (`crates/ra-asm-lift/src/lib.rs`) — lifts every function of an `Analysis`: the `Image`, the `&Analysis` and a `LiftOptions` (`standalone`, the `x87` unit); gives `Lifted`, which `raise_options(level)` raises.
- `Host` (`crates/ra-asm-ir/src/interp/mod.rs`) — the trait the interpreter calls for a function the module does not define: `call(&mut self, vm, name, ty, args) -> Result<Value, Stop>`; the lift's runtime and import host is `crates/ra-asm-lift/src/run/host.rs`, the replayer's `crates/ra-asm-verify/src/replay.rs`.
- `Vm::call_named` (`crates/ra-asm-ir/src/interp/mod.rs`) — calls a module function by name on a `Vm::new(&Module, Memory)`: the `&mut dyn Host`, the name and a `Vec<Value>` of arguments; a host calls back into the module with it.
- `emit_unit` / `emit_unit_dropping` (`crates/ra-asm-emit/src/c.rs`, the C and C++ emit; `lib.rs` only re-exports) — write a module as a C `Unit`: the `&Module` and an `Options` (`dialect`, `guest32`, `classes`, `hand`, `checks`); the second takes `&mut Module` and drops each function's IR once its source is written, a run of functions at a time, and is what `ras emit` (`apps/ras/src/emit.rs`) and the pipeline call; the tests call the first and check the second against it.
- `parts` (`crates/ra-asm-emit/src/c.rs`) — the whole-program pass before any function is written: the includes, externs, prototypes, globals and their layouts, the struct types, the C++ classes and the adapters, read from every function's IR into a `Parts`, whose `functions` then writes the bodies and `unit` joins them.
- `par_map` (`crates/ra-asm-emit/src/c.rs`) — runs the per-function emit on scoped threads with a 64 MB stack (`STACK`) that take small batches from a shared counter, in order; not rayon. The raise has its own in `crates/ra-asm-lift/src/raise/abi.rs`, on the default stack.
- `ra-asm-verify` (`crates/ra-asm-verify/src/lib.rs`) — `record(&Image, &Lifted, &Options)` takes a run's function vectors, `replay(&Image, &Lifted, RaiseLevel, &[Vector])` and `replay_abi(.., &signatures, ..)` run them again and give the `Failure`s. That per-function replay is the only replay: no host feeds a recorded session's answers back to a run, so a card that says a session "replays" means record it again and compare the two recordings.
- A new runtime shim lands in four places: the `%State` model and the runtime globals in `crates/ra-asm-lift/src/state.rs`, the C runtime in `runtime/driver.c`, the Rust runtime in `runtime/rhipper.rs`, and the interpreter host in `crates/ra-asm-lift/src/run/host.rs`; a 32-bit name also maps in `x86_shim` (`crates/ra-asm-lift/src/raise/prototypes.rs`), and `ras doctor` reads `driver.c`'s definitions one per line ending in `{`.

## Build and checks

- Two tiers of tests. The fast tier is `cargo test -q`: every test target the default features build, no tool but cargo, under five minutes on a warm build; it is the landing gate, and `.github/workflows/build.yml` runs it on every push. The slow tier is the oracles behind the `oracle` feature of `ra-asm-lift`, `ra-asm-emit` and `ras` (`cargo test -q -p <crate> --features oracle`, the feature is per package); `.github/workflows/nightly.yml` runs them, and a card whose change touches the lift or the emit runs the one it touches.
- A card's acceptance is its check: `cargo test -q` unless the acceptance names another cargo command in backticks. Run it before reporting. The run's environment carries `CARGO_BUILD_JOBS=6` (from `rhipper.toml`): the machine has little RAM and a full-parallel build swaps, so never raise it.
- `rhipper.toml` also allows the worker `clang`, `clang++`, `clang-cl`, `lld-link`, the `llvm-*` tools, `cmake`, `ninja` and `target/debug/ras.exe`, so a port can be built and traced by hand as described below; a command the allowlist refuses is refused for the whole run, so stay with these.
- The slow tier needs LLVM on the PATH: `clang`, `clang++`, `lld`, `llvm-objdump`, `llvm-readobj`, `llvm-symbolizer`; `cargo` for the Rust oracle. Tests that need a tool skip with a message when it is absent; a skip is not a pass.
- `cargo clippy --all-targets` warns with the pedantic set (the allows are in `Cargo.toml`); a change adds no warning. `cargo fmt` (width 140, `use_small_heuristics = "Max"`) on what you touched. Edition 2024, let chains allowed.
- `cargo test` does not always relink `apps/ras`'s binary for the integration tests: run `cargo build -q` first when a `ras` test looks stale.
- The oracles: `crates/ra-asm-lift/tests/oracle.rs` lifts every fixture at the machine, promoted and ABI (standalone) levels, compiles the `.ll` with clang beside `runtime/driver.c`, runs it and compares with `testdata/expected`; `crates/ra-asm-emit/tests/oracle.rs` does the same for the C, C++ and Rust outputs; `apps/ras/tests/pipeline.rs` runs the whole pipeline and `apps/ras/tests/smoke.rs` walks System32. All of them are the slow tier. A fixture program joins all of them.
- A hand port for debugging: `target/debug/ras.exe emit <exe> --out out/<name> --quiet`, then clang on `out/<name>/*.c` plus `runtime/driver.c` with `-I out/<name> -I runtime -fuse-ld=lld -lkernel32` (`-Wl,/largeaddressaware:no` for a 32-bit program; pass `-Wl,...` through a PowerShell array, the shell mangles it inline). Name the port `out/<name>/port.exe` (`port-t.exe` for a traced build) and run it bare in Bash as `./out/<name>/port.exe`, with no pipe and no PowerShell `&`: the worker's allowlist runs `out/*/*.exe` that way without approval. `-DRA_TRACE` prints every lifted function entered on stderr; a crash prints `ra: exception <code> at <host address> (module+<offset>)`, and `llvm-symbolizer --obj=<port.exe> 0x140000000+<offset>` on a `-g -gcodeview` build names the function and its line. There is no debugger on this machine.

- `ras lift` and `ras disasm` cut their own output, so neither needs `grep`, `head` or `Select-Object`: `--match <text>` keeps the lines that contain the text (case-insensitive; repeatable, a line holding any of them is kept), `--limit <n>` stops after n lines and ends with `... <k> more lines left out by --limit`. They cut the IR printed to stdout and the text of `disasm`, not `--json` or `lift --report`.
- `ras emit --quiet` hides the lift's warnings; without it every unsupported instruction prints with its address. The grade of a function is its trap count; a lift that guesses is a bug.
- A raise that hangs on a large program: `ras case --pass promote` gives up before any work there and has no per-step timer, so it names nothing. The bisection that works is `ras lift --only <addr> --level machine|promoted <exe>`, one function (and its callees) at a time: the address whose promoted lift does not finish while its machine lift does is the function to look at.
- No card measures a program or file outside the workspace, and no worker builds release for a measurement: the pairing session measures the large reference program after the cards land. A card that asks for figures (timings, trap counts, function counts, sizes) takes them on the `testdata/bin` fixtures with `target/debug/ras.exe`, and its report says so.

## Conventions

- Match the surrounding code: its comment density, naming and idiom. Doc comments say what and why, not how; a comment inside a function names the reason, not the step. No `TODO`s: an open end becomes a card or a line in the card's report.
- The lift is exact or it stops: an instruction the lift does not cover becomes a trap that names its address, never an approximation. Readability work (widths, names, idioms) keeps every oracle green; a new behaviour comes with a fixture that exercises it and its expected output from the native run.
- No compatibility with the old pipeline's files, names or conventions (Ghidra's corpus, the fidelity scores, `FUN_`/`GEN_` names): the engine writes its own shapes and the workbench reads those.
- The 32-bit port of a program is a 64-bit executable linked without large-address awareness that keeps the program's 32-bit pointers (roadmap decision 8); the machine and promoted levels map the image at its base and cannot run a 32-bit program that uses the C runtime.
- Names: an unnamed function is `F_<address>` in the IR, the C and the table; an address-taken x86 function has a universal entry `U_<address>`; runtime symbols are `ra_*`.
- `../rhipper-ide` is the consumer: when the JSON of `ras serve`, `functions.json` or `rhipper.json` changes, say so in the report so the workbench and its `docs/rhipper/rhipper-asm.md` follow. Never touch `../rhipper-agent`.
- Read the files the card names first, by the regions the outline points at; search with Grep and Glob before exploring; do not read `rhipper.md` itself, the card's text is in your prompt.
- Never write a file with a shell heredoc or `Set-Content`; use the Write and Edit tools. Never run Python with the script on stdin. `Remove-Item` on repo files is blocked; leave a stray file and say so.
- Report what changed and what was verified in a few lines; the check decides whether the card is done, not the report. The person commits.
